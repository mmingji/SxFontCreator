# SxFontCreator 手写字体制作器

打印模板 → 照着格子手写 → 扫描回传 → 全自动切格提取手写字形 → 生成个人手写体字体（TTF / woff / woff2）。
纯前端、零后端、离线可用；**数据只保存在本机浏览器里**。

当前进度：阶段一步骤 1.1~1.9 已完成（工程脚手架、6919 字表、模板与更正册 PDF、选字与批次、扫描件预处理、**自动切格**、**字形提取**、**红圈识别**、**更正对应**、**矢量化与字体合成**），并已加入**模板排列方式**（默认按使用频率：最常用的字排在最前，约 15 页即可日常使用）—— 界面上可以直接生成并下载模板 PDF / 更正册；扫描件的切格、页序号与批次校验码比对、**整页方向不对时的自动转正**、"分离淡灰参考字、只留手写笔迹"、**红圈识别与剔除**、以及**从手写稿生成可安装的 TTF / woff / woff2** 都已在真实手写样本上验证（三份手写件 + 一份更正册共 79 个字形，见 `docs/samples/font-montage.png` 与 `docs/samples/SxFontCreator-sample.ttf`）。**生成的字体已按 Windows 认中文字体的要求补齐 OS/2 字段**（代码页 936、CJK 统一表意文字位、字重级 400、选择标志 REGULAR），并已**装机复测通过**（Word 里中文正常应用手写体、不再回退宋体；用 `npm run inspect:os2 <字体文件>` 可自证字段）。**已知待改进**：同等字号下手写体观感比系统字体偏小 —— 已按《待办与风险清单》一-5 处置：**书写格映射上限 900 → 1000（字面率 100%）**、越界判据改为"书写格映射出来的设计框"、纸面与界面文案改为"居中写满格子(笔画贴到格子边、别出格)"，同一批笔迹的字面高度中位 **0.734em → 0.815em**（宋体 0.910em）；**逐字按字面框规整**留待阶段三 3.1。**界面已改成向导式**（2026-10-04，B1 落地）：顶部 6 步流程条一次只显示一步 —— ① 选字与出模板 ② 手写与扫描 ③ 上传识别 ④ 更正核对 ⑤ 生成字体 ⑥ 下载安装；第 1 步里**选字是「当前选字 / 自定义选字」两级**、**生成范围默认单页试打**、并能看到**模板第一页的真实预览**（pdf.js 渲染真实 PDF，可翻到打印自检页）。**B2（上传识别 + 识别结果展示）也已完成**：第 3 步可以选批次并显式确认、多选上传扫描件、串行识别（可中止、边跑边显示），并给出**页级结果**（页号 / 批次校验码是否一致 / 方向是否自动纠正 / 四角误差 / 写出与可疑格数 / 失败原因）与**格级视图**（该页 136 格缩略图 + 判定覆盖，点单格放大看笔迹与统计）；页脚读不出的页可以拖动或填数字手选页序。**B3 已完成前两段**：① **字形落盘** —— 识别出的笔迹掩膜逐页存进 IndexedDB（PNG 无损、按「批次 + 页序」分片），**刷新或关掉浏览器后不用重扫**；② **更正核对** —— 第 4 步把「第 k 个被圈字 ↔ 更正册第 m 格」并排摆出来，可改派 / 删除 / 补录，确认后才生效（更正册的页脚校验码为 0，识别时按件类型与主区分开处理）。**待做**：字体合成界面、下载 zip（步骤 1.10，含 CSS + 使用说明 + 可双击的样张预览页）。

## 开发命令

```
npm install            # 若报 npm 缓存目录权限错误（EPERM），改用：npm install --cache .npm-cache
npm run dev            # 开发服务，浏览器访问 http://localhost:5173
npm run build          # 构建到 dist/
npm run charset        # 重新生成字表（读做字体网 V4.0 的 GBK 字序文件，源文件不入库）
npm run frequency      # 重新生成频次分级数据（GB2312 本地推算 + 通用规范汉字表，源字表不入库）
npm run charrank       # 重新生成频序数据（Jun Da 字频表，源文件是 GBK、缓存于 .font-sources/ 不入库）
npm run font-subset    # 重新生成参考字字体子集（读 .font-sources/ 下的霞鹜文楷，源字体不入库）
npm run inspect:os2    # 字体 OS/2 表体检（量"Word 认不认它当中文字体"，可传系统字体做对照）
npm test               # 全套：字表 + 频次 + 频序 + 选字 + 流程 + 图像算子 + 扫描预处理 + 切格 + 字形提取 + 红圈识别 + 上传识别 + 更正对应 + 字体构建 + 模板 + 渲染 + 构建 + 冒烟
npm run test:charset   # 只跑字表校验
npm run test:flow      # 只跑制作流程的状态推导（向导界面的判断来源）
npm run test:template  # 只跑模板 PDF 校验（版面几何 + 产物读回）
npm run test:render    # 只跑渲染验证（把 PDF 渲染成图做像素断言，并输出图）
npm run test:grid      # 只跑自动切格验证（合成件 + 真实样本夹具，夹具缺失时 SKIP）
npm run test:extract   # 只跑字形提取验证（分离参考字与手写笔迹，夹具缺失时 SKIP）
npm run test:marks     # 只跑红圈识别验证（真实红圈件 + 合成件，夹具缺失时 SKIP）
npm run test:scanflow  # 只跑上传识别的编排与收批闸门（纯逻辑 + 真件夹具整条跑，夹具缺失时只跑纯逻辑）
npm run test:glyphstore # 只跑字形落盘（掩膜 ⇄ PNG 往返无损 + 分片存储，需浏览器）
npm run test:correction # 只跑更正对应验证（纯逻辑 + 真件端到端，夹具缺失时跳过真件）
npm run test:fontbuild # 只跑矢量化 + 字体构建（会先用 vite 打一个测试专用 bundle）
npm run test:smoke     # 只跑冒烟验证（需先 build）
```

## 目录结构

| 目录 | 内容 |
| --- | --- |
| `src/lib/` | 图像处理、字体、版面与本地存储相关模块（复用参考项目的部分在文件头注明来源与改动） |
| `src/components/` | 界面组件（`App.vue` 是向导骨架；第 1 步 `TemplatePreview.vue`，第 3 步 `ScanUpload.vue`，第 4 步 `CorrectionConfirm.vue`，选字面板 `SelectionPanel.vue`，模板预览 `PdfPreview.vue`，未接入步骤的说明 `StepContent.vue`） |
| `src/store/` | 项目状态（Pinia），也是「导出项目包」的数据结构来源 |
| `src/data/` | 生成的数据：`charset.js`（6919 字表）、`frequency.js`（频次分级）、`charRank.js`（使用频率排序），均由脚本生成、请勿手改 |
| `public/fonts/` | 内置参考字字体子集（3.27MB，只含字表 6919 字）与它的 OFL 许可文本 |
| `scripts/` | 构建期脚本（字表转换、频次分级、频序、参考字字体子集化）与只读体检工具（`inspect-font-os2.mjs`：查字体的 OS/2 字段） |
| `test/` | 分层验证脚本：每轮跑相关脚本、提交前跑全套 |
| `docs/` | 需求、实施计划、决策记录、待办清单、提交历史、样例图 |
