# SxFontCreator 手写字体制作器

打印模板 → 照着格子手写 → 扫描回传 → 全自动切格提取手写字形 → 生成个人手写体字体（TTF / woff / woff2）。
纯前端、零后端、离线可用；**数据只保存在本机浏览器里**。

当前进度：阶段一步骤 1.1~1.10 与界面串联（B1 / B2 / B3）均已完成（工程脚手架、6919 字表、模板与更正册 PDF、选字与批次、扫描件预处理、**自动切格**、**字形提取**、**红圈识别**、**更正对应**、**矢量化与字体合成**、**打包下载**），并已加入**模板排列方式**（默认按使用频率：最常用的字排在最前，约 15 页即可日常使用）—— 界面上可以直接生成并下载模板 PDF / 更正册；扫描件的切格、页序号与批次校验码比对、**整页方向不对时的自动转正**、"分离淡灰参考字、只留手写笔迹"、**红圈识别与剔除**、以及**从手写稿生成可安装的 TTF / woff / woff2** 都已在真实手写样本上验证（三份手写件 + 一份更正册共 79 个字形，见 `docs/samples/font-montage.png` 与 `docs/samples/SxFontCreator-sample.ttf`）。**生成的字体已按 Windows 认中文字体的要求补齐 OS/2 字段**（代码页 936、CJK 统一表意文字位、字重级 400、选择标志 REGULAR），并已**装机复测通过**（Word 里中文正常应用手写体、不再回退宋体；用 `npm run inspect:os2 <字体文件>` 可自证字段）。**说明已整合（2026-10-07）**：向导每一步右上角都有「查看完整说明」—— 打开的是**单文件** `public/使用说明.html`（六节：打印 / 书写 / 扫描 / 上传与更正 / 生成与安装 / 常见问题，可离线看、可保存到本地），界面各步只留一句摘要（《决策记录》一-15）。**已知待改进**：同等字号下手写体观感比系统字体偏小 —— 已按《待办与风险清单》一-5 处置：**书写格映射上限 900 → 1000（字面率 100%）**、越界判据改为"书写格映射出来的设计框"、纸面与界面文案定为"**居中书写,别出格**"（"写满"的细则在界面分笔画多 / 笔画少两种情况讲，见《决策记录》一-13），同一批笔迹的字面高度中位 **0.734em → 0.815em**（宋体 0.910em）；**逐字按字面框规整已于 2026-10-07 放弃** —— 任何"统一字面大小"的做法都要缩放轮廓、必然改动手写笔画的粗细，用户不接受（见《决策记录》四-7）；句末这一档改由阶段三 3.2 的**字形体检告警**处理（越界 / 偏小 / 笔画过细，只提示、不改字形）。**界面已改成向导式**（2026-10-04，B1 落地）：顶部 6 步流程条一次只显示一步 —— ① 选字与出模板 ② 手写与扫描 ③ 上传识别 ④ 更正核对 ⑤ 生成字体 ⑥ 下载安装；第 1 步里**选字是「当前选字 / 自定义选字」两级**、**生成范围默认单页试打**、并能看到**模板第一页的真实预览**（pdf.js 渲染真实 PDF，可翻到打印自检页）。**第 1 步的预览是并排两块（2026-10-07）**：左边是真的会打印出来的模板，右边是**填写示意** —— 与模板同版式，但每个书写格里已用内置手写体（悠哉字体 Yozai ## 开发命令

```
npm install            # 若报 npm 缓存目录权限错误（EPERM），改用：npm install --cache .npm-cache
npm run dev            # 开发服务，浏览器访问 http://localhost:5173
npm run build          # 构建到 dist/（交付形态：IIFE 单包 + 按需内联；双击 dist/index.html 即用）
npm run pack           # 构建后打成可分发的 zip（release/SxFontCreator-<版本>-便携版.zip，解压双击即用）
npm run charset        # 重新生成字表（读做字体网 V4.0 的 GBK 字序文件，源文件不入库）
npm run charrank       # 重新生成频序数据（Jun Da 字频表，源文件是 GBK、缓存于 .font-sources/ 不入库）
npm run font-subset    # 重新生成参考字字体子集（读 .font-sources/ 下的霞鹜文楷，源字体不入库）
npm run handwriting-subset # 重新生成「填写示意」用的手写体子集（读 .font-sources/ 下的悠哉字体，源字体不入库）
npm run guide          # 重新生成《使用说明》单文件页（内容源 src/lib/guide.js → public/使用说明.html）
npm run inspect:os2    # 字体 OS/2 表体检（量"Word 认不认它当中文字体"，可传系统字体做对照）
npm test               # 全套：字表 + 选字分类 + 频序 + 选字与批次 + 流程 + 使用说明 + 浏览器兼容 + 图像算子 + 扫描预处理 + 切格 + 字形提取 + 红圈识别 + 上传识别 + 更正对应 + 字体构建 + 字体预览 + 项目包 + 字形体检 + 总览图 + 模板 + 渲染 + 构建 + 分发 zip + file:// 形态实测 + 冒烟（默认以 file:// 打开）
npm run test:charset   # 只跑字表校验
npm run test:flow      # 只跑制作流程的状态推导（向导界面的判断来源）
npm run test:guide     # 只跑《使用说明》校验（内容源结构 + 产物是单文件、六节齐全）
npm run test:browser   # 只跑浏览器兼容（九项能力检测 + polyfill 行为 + 源码/产物静态扫描，纯 Node）
npm run test:template  # 只跑模板 PDF 校验（版面几何 + 产物读回）
npm run test:render    # 只跑渲染验证（把 PDF 渲染成图做像素断言，并输出图）
npm run test:grid      # 只跑自动切格验证（合成件 + 真实样本夹具，夹具缺失时 SKIP）
npm run test:extract   # 只跑字形提取验证（分离参考字与手写笔迹，夹具缺失时 SKIP）
npm run test:marks     # 只跑红圈识别验证（真实红圈件 + 合成件，夹具缺失时 SKIP）
npm run test:scanflow  # 只跑上传识别的编排与收批闸门（纯逻辑 + 真件夹具整条跑，夹具缺失时只跑纯逻辑）
npm run test:glyphstore # 只跑字形落盘（掩膜 ⇄ PNG 往返无损 + 分片存储，需浏览器）
npm run test:correction # 只跑更正对应验证（纯逻辑 + 真件端到端，夹具缺失时跳过真件）
npm run test:fontbuild # 只跑矢量化 + 字体构建（会先用 vite 打一个测试专用 bundle；含"从落盘掩膜构建"）
npm run test:fontpack # 只跑字体打包（zip 内容 / 使用说明 / 预览页，纯 Node）
npm run test:fontpreview # 只跑网页字体预览的纯逻辑（文本拆分 / 收录判定 / 默认文本 / 族名，纯 Node）
npm run test:projectpack # 只跑项目包导出 / 导入（包结构 / 校验分支 / 往返保真，纯 Node）
npm run test:checkup   # 只跑字形体检（合成掩膜逐条钉住六条阈值 + 几何与构建同源，纯 Node）
npm run test:overview  # 只跑字形总览图（排布计算 / 缩放 / 边界 / 图上文字口径，纯 Node）
npm run test:smoke     # 只跑冒烟验证（需先 build）
npm run test:file      # 只跑 file:// 形态实测（需先 build；量浏览器能力 + 内联资源按需载入 + 预览渲染）
npm run test:pack      # 只跑分发 zip 校验（需先 build；包内容与 dist 一一对应 / 逐字节一致 / 中文名带 UTF-8 标志，纯 Node）
```

## 目录结构

| 目录 | 内容 |
| --- | --- |
| `src/lib/` | 图像处理、字体、版面与本地存储相关模块（复用参考项目的部分在文件头注明来源与改动） |
| `src/components/` | 界面组件（`App.vue` 是向导骨架；六个步骤分别是 `TemplatePreview.vue` / `StepContent.vue`（手写与扫描的说明）/ `ScanUpload.vue` / `CorrectionConfirm.vue` / `BuildFont.vue` / `ResultDownload.vue`，另有选字面板 `SelectionPanel.vue`、模板预览 `PdfPreview.vue`、第 3 步的批次管理弹窗 `BatchManager.vue`、第 6 步的网页字体预览 `FontPreview.vue`，以及顶栏的项目备份入口与弹窗 `ProjectBackup.vue`） |
| `src/store/` | 项目状态（Pinia），也是「导出项目包」的数据结构来源（`projectData()` 是落盘的**唯一字段清单**，正常落盘、关页兜底与导出共用） |
| `src/data/` | 生成的数据：`charset.js`（6919 字表）、`charRank.js`（使用频率排序），均由脚本生成、请勿手改（选字分级不落数据文件：`src/lib/frequency.js` 运行时按 GB2312 区位码推算） |
| `public/fonts/` | 内置字体子集与许可文本：参考字用的霞鹜文楷子集（3.27MB）、「填写示意」用的悠哉字体子集（3.84MB，OFL-1.1），两者都只含字表 6919 字。**交付产物里这两个 ttf 不再复制**——它们被内联进 `assets/inline-font-*.js`（按需加载），只有许可文本随产物分发 |
| `scripts/` | 构建期脚本（字表转换、频次分级、频序、参考字字体子集化、分发打包 `pack-dist.mjs`）与只读体检工具（`inspect-font-os2.mjs`：查字体的 OS/2 字段） |
| `test/` | 分层验证脚本：每轮跑相关脚本、提交前跑全套 |
| `docs/` | 需求、实施计划、决策记录、待办清单、提交历史、样例图 |
